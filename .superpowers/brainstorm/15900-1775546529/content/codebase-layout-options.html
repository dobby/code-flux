Codebase Page Structure

Choosing how much growth history belongs on the same page as the current-state treemap.

A. Compact Growth + Treemap
Growth
Current Structure

Recommended

Small dual-line growth chart at the top, then the treemap and breakdowns as the main focus.

B. Deep Mixed Page

One big analytics page

More charting, more controls, more context. Powerful, but it risks diluting the “current state first” principle.

C. Separate Growth Page
Growth
Codebase

Strict separation

Cleanest semantics, but likely over-segments the product at this stage and creates an extra page before the core views mature.

My recommendation: start with A. It keeps the Codebase page grounded in current structure, while still giving the user the growth context they clearly want. If that compact top section proves too constraining later, it can graduate into its own page without rethinking the underlying data model.
